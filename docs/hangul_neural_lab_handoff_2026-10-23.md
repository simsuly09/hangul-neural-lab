## 2. 프로젝트 목표와 사용자 요청

한글 한 글자를 쓰면 인공신경망이 글자를 인식하고, 실제 입력·학습된 가중치·중간 활성값을 바탕으로 처리 과정을 3D로 보여주는 교육용 웹앱이다.

자료 전체를 채팅창에 다시 업로드하는 방식은 용량 때문에 적합하지 않다. 연결된 작업 환경에서 로컬 자료를 읽고 학습용 목록을 생성하는 방향으로 진행한다.

### 4.3 현재 배포된 모델

현재 모델은 우리가 새로 학습한 모델이 아니다. AI Hub 제공 모델을 브라우저에서 실행하도록 변환한 것이다.

| 항목 | 값 |
| --- | --- |
| 입력 | 64 × 64 × 3, RGB, 값 0~1 |
| 구조 | 초성·중성·종성용 독립 CNN 3개, 입력 공유 |
| 출력 | 초성 19개, 중성 21개, 종성 28개 |
| 종성 없음 | 28개 종성 클래스 중 하나 |
| 분기별 구조 | 입력, 합성곱 12층, 최대 풀링 4층, Flatten, 출력층 |
| 분기별 표시 단계 | 19개 |
| 고유 계산 층 | 55개 |
| 학습 파라미터 | 2,751,604개 |
| 모델 설명 파일 | `model/network.json`, 37,430바이트 |
| 가중치 파일 | `model/weights.bin`, 11,006,416바이트 |

19개 분기 단계를 세 화면에 표시한다고 해서 57개의 고유 층을 계산하는 것은 아니다. 공통 입력을 제외한 후속 층은 각각 18개이므로 총 고유 층은 55개다.

## 5. 완료한 웹앱 작업

### 5.1 입력과 모델 로딩

- 그림판에서 마우스나 터치로 한 글자를 입력한다.
- 획 두께 조절, 되돌리기, 모두 지우기를 지원한다.
- 이미지 파일을 불러올 수 있다.
- 직접 코드로 그린 ‘가·나·다’ 기본 예시를 제공한다. 원본 데이터셋에서 가져온 예시가 아니다.
- 입력 글자의 경계를 찾아 비율을 유지하고 여백을 정리한 뒤 64×64 RGB로 변환한다.
- 기본 모델은 접속 시 자동으로 준비된다.
- `network.json`과 `weights.bin`을 함께 선택하는 기능도 있다.
- 선택 모델은 IndexedDB에 기억하거나 지울 수 있다.
- 입력 이미지와 선택 파일을 추론 서버로 보내지 않고 브라우저에서 처리한다.

### 5.2 실제 추론과 3D 시각화

- TensorFlow.js로 전체 계산 그래프를 실행한다.
- Three.js로 실제 중간 활성값을 표시한다.
- 세 분기의 같은 층을 같은 시간에 보여준다.
- 단계가 바뀔 때 카메라가 자동으로 현재 층을 확대한다.
- 합성곱·풀링의 입력 영역과 출력 위치를 연결해 표시한다.
- 특징이 펼쳐지는 동작과 일부 완전연결 선을 표시한다.
- 완전연결 선에는 실제 입력 활성값과 가중치의 곱을 반영한다.
- 실제 합성곱 입력 영역, 필터, 편향, 가중합, ReLU 출력을 수치로 볼 수 있다.
- 일시정지 상태에서는 화면을 드래그해 회전하고 확대·이동할 수 있다.

추론에는 전체 채널과 값을 사용하지만, 3D 화면은 최대 4개 채널과 일부 공간 위치를 샘플링한다. 모든 노드·연결을 빠짐없이 그리는 것은 아니다. 화면 밝기도 표시용으로 조절하므로 색상 자체를 원래 수치와 동일시하지 않는다.

### 5.3 재생과 결과 공개

- 초성·중성·종성 공통 19단계 타임라인을 사용한다.
- 1배속 재생 길이는 34초다.
- 0.5배, 1배, 2배, 4배 속도를 지원한다.
- 재생·일시정지, 이전·다음 단계, 재생 위치 이동을 지원한다.
- 주요 단계 바로가기: 입력, 특징 1~4, 펼치기, 분류.
- 주요 단계 바로가기는 해당 지점으로 이동한 뒤 일시정지한다.
- 영상이 끝난 뒤에만 인식 글자, 소리별 확률, 조합된 후보를 공개한다.
- 다시 재생하거나 완료 이전으로 되감으면 결과를 다시 숨긴다.
- 새로운 입력으로 이전 추론을 취소하며 늦게 도착한 이전 결과도 무시한다.

재생 영상은 이미 계산한 활성값을 설명하는 과정이다. 34초는 모델의 실제 추론 시간이 아니다. 단계별 설명을 위해 일부러 늘린 시간이다.

후보 글자의 순위는 초성·중성·종성 출력 확률의 곱으로 계산한다. 이것을 보정된 실제 정답 확률로 해석하면 안 된다. Softmax 예측 확률과 평가 데이터에서 측정한 정답률도 구분해야 한다.

### 5.4 UI·UX 개선

사용자가 제공한 기존 화면 캡처 3장을 보고 다음 문제를 정리했다.

- 안내 글씨와 탭이 작고 정보가 촘촘했다.
- 고급 모델 설정이 크게 노출돼 시작 동작이 분산됐다.
- 그림판과 재생 조작부의 위계가 불분명했다.

개선 내용:

- ‘글자 쓰기 → 신경망 보기 → 결과 확인’ 순서 안내.
- 그림판, 버튼, 안내 문구 확대.
- 데스크톱에서 입력 옆에 넓은 신경망 영역 배치.
- 모바일에서 세 신경망을 위아래로 배치.
- 모델 설정, 전처리 이미지, 층별 수치는 기본적으로 접어서 표시.
- 재생 속도와 경과 시간 표시.
- 주요 7단계 바로가기.
- 상세 분기 탭과 결과 확률 탭 동기화.
- 키보드 방향키로 탭 이동 지원.
- 완료 후 결과 영역으로 이동.
- ‘다른 글자 써보기’로 그림판을 비우고 입력 위치로 이동.

사용자가 이후 “웹사이트는 이제 ㅇㅋ”라고 했으므로 현재 화면을 기준 버전으로 보존한다. 다음 작업에서 필요 없는 전체 디자인 변경을 반복하지 않는다.

## 8. 경량 모델 학습 계획

이 절은 논의한 제안이며 구현·학습 완료 내역이 아니다.

### 8.1 핵심 방향

현재 제공 모델은 세 분기가 독립적으로 특징을 추출한다. 자체 모델은 특징 추출부 하나를 공유하고 마지막 출력만 초성·중성·종성으로 나누는 구조부터 시도한다.

최적화 대상은 주로 배포 후 추론 시의 계산량과 메모리다. 학습 비용도 관리하되, 적은 학습 데이터만 사용했다고 추론 비용이 줄어드는 것은 아니다.

### 8.2 첫 후보 구조

```text
입력: 32 × 32 × 1 흑백
Conv2D: 3 × 3, 16채널, same, ReLU
MaxPooling2D: 2 × 2
Conv2D: 3 × 3, 32채널, same, ReLU
MaxPooling2D: 2 × 2
Conv2D: 3 × 3, 64채널, same, ReLU
MaxPooling2D: 2 × 2
GlobalAveragePooling2D
독립 Dense 출력 3개: 초성 19, 중성 21, 종성 28
```

별도 BatchNorm이나 숨은 Dense 없이 각 합성곱·출력층에 bias를 포함하는 위 구조의 계산상 파라미터 수는 27,716개다.

- 합성곱 1: `(3*3*1 + 1)*16 = 160`
- 합성곱 2: `(3*3*16 + 1)*32 = 4,640`
- 합성곱 3: `(3*3*32 + 1)*64 = 18,496`
- 세 출력 합계: `(64 + 1)*(19 + 21 + 28) = 4,420`

FP32 가중치만 계산하면 110,864바이트, 약 0.11MB다. 현재 가중치 약 11MB와 비교하면 약 100분의 1이지만 모델 설명, 라이브러리, 중간 활성값, 브라우저와 GPU의 메모리는 별도다. 처리 속도가 100배 빨라진다고 단정하면 안 된다.

32×32에서는 복잡한 획 정보가 줄어들 수 있다. 같은 구조의 48×48 입력을 비교하고 필요하면 구조를 조정한다. Global Average Pooling을 쓰는 이상 입력 해상도가 달라져도 위 파라미터 수는 같지만 계산량과 활성값 메모리는 달라진다.

이 구조는 성능이 검증된 최종 설계가 아니라 작은 기준 모델이다. 공간 정보를 평균내는 방식이 한글 구별에 불리한지 평가하고, 필요하면 작은 공간 격자를 유지하는 대안도 비교한다.

### 8.3 학습 데이터 준비

- 자료에서 한글 한 글자 이미지와 정답을 연결한다.
- 먼저 완성형 한글 음절을 대상으로 삼고, 다른 문자·기호의 처리 범위는 별도 정의한다.
- 정답 음절을 초성·중성·종성 인덱스로 분해한다.
- 기존 모델과 출력 라벨의 순서를 맞춰 비교 가능하게 한다.
- 작성자 정보가 있으면 작성자 기준으로 학습·검증·평가를 분리한다.
- 같은 작성자나 중복 이미지가 양쪽에 섞이지 않는지 확인한다.
- 공식 데이터 분할이 있으면 먼저 그 의미와 작성자 중복을 확인한다.
- 작성자 정보가 없다면 가능한 원본 문서·수집 단위로 묶고 평가의 한계를 기록한다.
- 웹과 학습의 자르기, 여백, 흑백 변환, 정규화 조건을 맞춘다.
- 작은 회전·이동·획 두께 변화는 학습 데이터에만 적용한다.
- 일부 자료로 코드 실행을 확인한 뒤 자모·글자 분포를 살펴 확대한다.
- 대용량 원본을 전부 메모리에 올리지 않고 파일 목록 기반으로 배치 로딩한다.

### 8.4 학습·개선 순서

1. 정답 라벨만으로 작은 모델을 처음부터 학습한다.
2. 검증 데이터로 모델 선택과 조기 종료를 수행한다.
3. 선택한 모델을 고정된 평가 데이터에서 기존 모델과 비교한다.
4. 필요하면 같은 작은 구조에 지식 증류를 적용한다.
5. 마지막에 양자화 전후를 비교한다.

학습 도구는 Python과 TensorFlow/Keras를 우선 후보로 두었다. 아직 환경 설치나 학습 스크립트 작성은 시작하지 않았다. 배치 크기, 학습률, 에폭 수는 장치와 데이터 확인 후 정한다.

지식 증류는 기존 모델의 후보별 점수도 참고하게 하는 방식이다. 기존 모델의 오류를 그대로 따르지 않도록 실제 정답 손실을 함께 사용한다. 증류를 하더라도 서비스 시에는 작은 모델만 실행할 수 있다. 비교의 의미를 분명히 하려면 정답만으로 학습한 작은 모델도 별도로 남긴다.

양자화는 다운로드 용량 절감과 실제 연산·실행 메모리 개선을 구분해서 평가한다. TensorFlow.js의 저장 가중치 양자화만으로 브라우저 전체가 INT8로 계산되거나 메모리가 4분의 1이 된다고 가정하지 않는다.

### 8.5 비교 지표

| 지표 | 평가 방법 |
| --- | --- |
| 완성 글자 정확도 | 세 구성요소가 모두 맞은 비율 |
| 초성·중성·종성 정확도 | 각 출력의 정답률 |
| 오류 분포 | 자주 틀리는 자모·글자와 클래스별 표본 수 |
| 가중치·배포 파일 크기 | 실제 파일 바이트 수 |
| 계산량 | 파라미터 수와 연산량 추정 |
| 첫 실행 시간 | 모델 로딩과 초기화 비용을 구분 |
| 반복 추론 시간 | 같은 기기·백엔드, batch 1, 워밍업 후 중앙값·P95 |
| 실행 메모리 | 측정 가능한 텐서 규모와 도구·측정 범위 명시 |
| 시각화 포함 비용 | 추론만 실행한 경우와 별도로 측정 |

기존 모델과 자체 모델은 같은 원본 평가 이미지·정답을 사용한다. 입력 크기 등 모델별 필요한 전처리는 각 모델에 맞게 적용하되 조건을 기록한다.

3D 영상 재생 시간은 추론 시간으로 쓰지 않는다. 중간 활성값 전체 보관과 세 개의 WebGL 화면은 별도 비용이므로 추론 성능 평가에서는 끄거나 분리 측정한다. 배터리·전력은 실제 측정 없이 속도나 파라미터 수만으로 수치를 추정해 확정하지 않는다.

### 8.6 웹에 연결할 때 반드시 해결할 호환성

현재 업로드 UI가 있다는 이유만으로 임의의 새 모델을 바로 읽을 수 있는 것은 아니다.

- `runtime.mjs`의 모델 검증은 현재 포맷, 55개 층, 64×64×3 입력, 11,006,416바이트 가중치 등 기존 모델 조건에 고정돼 있다.
- 현재 연산 처리와 시각화는 Input, Conv2D, MaxPooling2D, Flatten, Dense 중심이다.
- 제안한 GlobalAveragePooling2D와 흑백·가변 해상도 입력은 지원을 추가해야 한다.
- 세 분기가 입력 이외의 특징 추출부도 공유하는 새 구조에 맞춰 층 추적과 중복 계산 표시를 점검해야 한다.
- 현재 19단계 타임라인과 7단계 바로가기는 기존 구조에 맞춰져 있다. 다른 모델에도 그대로 적용하면 안 된다.
- 중간 활성값이 필요한 교육용 실행과 최종 출력만 필요한 저비용 추론 실행을 구분하는 것이 좋다.

먼저 학습·평가를 완성한 뒤 모델 포맷·로더·시각화 호환성을 순서대로 확장한다. 기존 배포 모델 파일을 시험용 가중치로 덮어쓰지 않는다.

   - 필요하면 48×48 입력을 비교하고, 정확도 손실과 자원 절감 사이의 선택 근거를 기록한다.

7. **추가 경량화 실험**
   - 정답 학습 모델을 보존한 채 지식 증류를 실험한다.
   - 양자화 전후의 정확도와 실행 환경별 효과를 확인한다.
   - 개선이 실제로 확인된 모델을 선택한다.

8. **웹 연동과 최종 비교 페이지**
   - 새 구조에 맞는 내보내기·로딩·중간 활성값·재생 단계를 지원한다.
   - 기존 모델과 자체 모델의 추론 및 결과를 비교하는 화면을 구현한다.
   - 모델 예측 확률, 평가 정확도, 실제 추론 시간, 설명 영상 시간을 구분해 표시한다.
   - 추론만 수행하는 저비용 모드와 3D 교육 모드의 비용을 구분한다.
